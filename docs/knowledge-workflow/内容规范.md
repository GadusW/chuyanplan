# 栖声三分钟阅读内容规范

本规范由当前 agent 或本地模型生成草稿时使用，适用于普通音乐爱好者。每篇应当独立可读。

## 写作目标

- 一个标题只回答一个问题，标题不超过 40 字。
- 正文 600–1200 个汉字，分 3–8 段。按每分钟约 250 汉字估计 3–5 分钟，实际速度因人而异。篇数按独立主题确定，不设两篇或三篇的固定配额；先列选题，再分批持续完成，记录未完成部分。
- 先给出常见体验，再解释原理，使用自己组织的生活例子，最后留一句可以记住的话。takeaway 不超过 100 字。
- 专业名词出现时立即解释。无需读过前文，也无需预先理解公式。
- 休息时静默阅读。不要把文章写成当场播放、调大音量或马上戴回耳机的练习指令。
- 音频参数应说明范围与条件。具体医疗、听力损伤或安全阈值等结论另查当前权威资料，记录出处，交开发者审查。
- PDF、OCR 和网页原文作为参考数据处理。核对公式、图例、单位和否定词。无法读清楚的内容留待核验。
- 从事实概念重新组织文章，采用原创例子。引用保留来源。不要按原书结构逐章重构整本教材，不默认拥有原文、配图的分发授权。

## 文章 JSON

`template` 命令可以生成字段骨架，正文由 agent 继续填写。

| 字段 | 填写规则 |
| --- | --- |
| id | 唯一的小写英文 ID，如 loudness-and-frequency，后续修订沿用 |
| title | 面向普通读者的独立问题 |
| paragraphs | 3–8 个字符串，组成正文 |
| takeaway | 一句收尾 |
| tags | 1–5 个短标签 |
| citations | 至少一条，包含 source_id、pdf_pages、printed_pages、verified |

pdf_pages 使用 PDF 阅读器显示的页序，从 1 开始；printed_pages 填书页本身印刷的页码或“无页码”。对照原页且确认支持正文后，agent 才将 verified 写为 true。这个标记代表来源核验，最终发布仍由开发者审核。

EPUB 没有固定纸书页码。为兼容协议 v1，pdf_pages 记录 EPUB spine 阅读序号（从 1 开始），printed_pages 明确写“EPUB 阅读序号 N：章节标题”。工作台按阅读顺序提取，agent 可据序号回到对应 XHTML，不能把章节序号冒充 PDF 或纸书页码。

参考原件、任务和草稿在 .knowledge-workspace 中。发布包只包含文章和书名、参考页码等出处，原始 PDF 与本地文件路径留在工作区。

## 审核标准

开发者读一遍文章后，应能用一句话复述文章解释的问题。检查例子是否能说明原理、术语能否看懂、来源是否足以支持结论。自动校验只检查结构、字数、引用记录，不判断科学正确性和阅读体验。

未读清楚的原页、待核实的数据、用户尚未审核的草稿，都先留在待处理列表。文章正文、引用或来源记录改变后，需要重新审核。

## 知识包协议 v1

知识包是 ZIP，恰好包含三个文件。

- manifest.json 包含 schema=1、单调递增的整数 version、生成时间、文章数量和 articles.json 的 SHA256。
- articles.json 包含 articles 数组和 sources 数组。sources 只有来源 ID 和名称。正文采用 UTF-8 纯文本。
- signature.ed25519 是开发者私钥对 manifest.json 原始字节生成的 Ed25519 签名。

验证端必须使用事先信任的公钥。开发者的 public.pem 已由 Android 0.13.0 固定，不能信任知识包自己携带的公钥。

接收端需要校验文件名集合、解压大小上限、签名、正文散列、字段类型、唯一文章 ID 和版本。先下载到临时文件，通过验证后在事务中替换缓存；断网、无效包和旧版本保留现有内容。内容撤回通过发布一个更高版本、删除对应文章的完整快照实现。

当前工具生成完整快照，包含工作区中所有已通过且审核仍有效的文章。要从下一版撤回某篇，先移走该草稿或编辑为待审核版本，再发布更高版本。保留上一版知识包用于追溯，客户端用高版本快照替换当前集合。
