# 栖声 Android 开发与验收说明

当前版本：0.8.0。原生 Kotlin / Compose 应用，最低 Android 8.0，目标 API 36。已实现全屏／歌词、五维媒体库、离线声音画像、系统播放卡片、体感沉浸与播放历史恢复。详见 [更新日志](../CHANGELOG.md)、[声音画像](audio-analysis.md)、[体感沉浸](immersive-mode.md) 和 [播放历史](playback-history.md)。

## 导入与音乐库

参考海贝音乐「扫描建立本地曲库、歌曲／专辑／文件夹浏览」的工作方式，使用自己的界面与实现，不复制其品牌或页面。参考：[HiBy 官方用户指南](https://guide.hiby.com/en/docs/products/audio_player/hiby_r6iii_2025/guide/)。

1. 首次授权音频访问后，自动扫描 Android 系统音频媒体库。每次新建应用会话可刷新；不会无限循环扫描。
2. 「导入音乐 → 扫描手机音乐」扫描系统库，并重新扫描已经持久授权的目录。包括系统媒体库尚未索引的歌曲时，应选择对应文件夹。
3. 「选择音乐文件夹」使用系统 SAF 选择器授权，递归读取子目录。可选择可用的 SD 卡目录，但不能绕过系统对根目录、Android/data 等位置的限制。
4. 「导入音频文件」通过系统文档选择器多选，只保存可持久读取的文件位置。不复制、不转码、不写入原文件，不申请所有文件访问权限。导入和普通播放不需要录音授权；体感节奏效果按需请求 Visualizer 所需的 RECORD_AUDIO，不采集麦克风。
5. 可选跳过不足 60 秒或小于 100 KB 的音频；默认关闭，避免漏掉前奏、间奏。未知时长不会因时长过滤而直接丢弃。过滤只影响曲库索引。
6. 同一 URI 重复导入会更新而非新增。系统媒体库与标准外部存储 SAF URI 通过卷名及相对路径归一，减少两种扫描入口的重复；第三方文件提供方无法确定物理文件身份时，不用文件名猜测去重。
7. 扫描可取消。成功扫描后才提交该来源的曲库更新；不会删除手机音乐文件。读取失败时显示提示，保留未能确认已消失的文件夹记录。

可搜索标题、艺术家、专辑、文件名，按歌曲／专辑／艺术家／文件夹／格式浏览，并筛选已识别的无损音源。Room 持久化索引；系统持久 URI 授权保存读取能力。权限撤销、文件移动或 SD 卡移除后，需要重新授权或扫描。

## 解码和输出

首版使用 **VideoLAN 官方 LibVLC 3.7.7**，将可读文件描述符交给原生解复用／软件解码库，通过 Android AudioTrack 输出。以此覆盖 ALAC，避免把厂商设备是否提供 ALAC MediaCodec 当成统一能力。原规划的 Media3 不是本版实际内核；系统控制通过 MediaSessionCompat 提供。

| 格式 | 首版验证 | 说明 |
|---|---|---|
| MP3 | 已验证实际解码、播放、跳转 | 有损音源，不会恢复编码时丢失的细节 |
| PCM WAV | 已验证实际解码、播放、跳转 | WAV 是容器，非 PCM 的特殊变体需单独验收 |
| FLAC | 已验证实际解码、播放、跳转 | 无损音源 |
| AAC / ADTS | 已验证实际解码、播放、跳转 | 有损音源；其他容器及配置需按样本验证 |
| ALAC / M4A | 已验证实际解码、播放、跳转 | 无损音源，读取 MP4 音频采样条目识别 ALAC |

其他可索引的音频格式走 LibVLC 能力，不能据此承诺每种编码、封装、位深、采样率或损坏文件都能播放。首轮自动化音频样本为 44.1 kHz 双声道，包含真实压缩后的文件，不只是改扩展名。

播放器不主动将原文件转成 MP3 / AAC，不启用 EQ 或变速处理。**文件解码、系统混音、传输和硬件转换是不同环节**：本版不承诺 bit-perfect、USB 独占直出、自动匹配 DAC 采样率或蓝牙全链路无损。扬声器、蓝牙、有线／USB 耳机由系统路由；界面显示检测到的连接类别并注明跟随系统，不冒充精确的实际输出流测量。

支持播放／暂停、进度跳转、上一首／下一首、队列、随机、单曲／列表循环和顺序播放。前台媒体服务保持后台播放，提供系统媒体会话和通知栏控制。音频焦点冲突会暂停或降低音量，耳机断开暂停。0.7.0 起持久保存队列与位置，重开保持暂停；播放中约每 3 秒存一次检查点，强制结束可能损失最后约 3 秒进度。

## 界面与结构

- 固定深靛蓝、暖月白、雾蓝品牌色；使用正式图案前景作为默认视觉。不随系统壁纸替换品牌色。
- Compose 原生控件与滑块，乐库／播放页淡入位移转场，迷你播放器展开收起，底部导入与队列面板。
- 列表使用稳定 URI key，业务状态由 ViewModel / StateFlow 提供，界面按生命周期订阅。耗时扫描与元数据读取运行于注入的 IO dispatcher。
- 单应用模块，内部按 `data`、`playback`、`ui`、`di` 分层，Hilt 注入依赖。首版避免过早拆出大量 Gradle 模块。
- Android 启动器直接引用已审核的自适应图标资源，图片没有被重新生成。

## 构建与验收

标准 Gradle Wrapper 已纳入仓库，固定 8.13 并校验官方分发包 SHA256；本机 SDK 路径、代理、下载缓存不提交。构建指令见 README。

已完成：

- 当前 0.8.0：21 个单元测试、17 个 API 36 设备测试、Lint 无错误；覆盖真实音频瞬态和渲染响应，见 [验证报告](validation/android-0.8.0.json)。
- 0.7.0：15 个 JVM 单元测试、15 个设备测试、Lint 无错误；版本与 APK 校验记录见 [验证报告](validation/android-0.7.0.json)。设备回归含 24 次波形效果器建立／释放、24 次沉浸界面切换，以及数据库 1→3／2→3 迁移、历史保存、重开恢复与非零位置解码。

- `:app:assembleDebug` 编译、打包并安装到 API 36 x86_64 模拟器。
- JVM 单元测试：格式判断、过滤边界、队列结束／循环、M4A 容器识别和畸形输入处理，以及 LRC 时间戳、偏移和纯文本。
- 五格式设备集成测试：系统媒体库扫描、重复导入去重、ALAC 标签识别、实际解码、时长、跳转进度、切换歌曲、后台播放、文件不可用提示及恢复。
- Compose 界面测试：导入入口、三种导入选项、关闭面板、乐库与播放页导航、队列与进度控件可达性。
- 模拟器手动验证系统 SAF 目录授权，成功导入父目录 ALAC 和嵌套子目录 FLAC。
- APK 原生库 ZIP 16 KB 对齐检查，以及 arm64-v8a 动态库 ELF LOAD 段 16 KB 对齐检查；不等同于已在 16 KB 真机运行。
- Android Lint 无错误；依赖有更新提示及资源兼容变体等非阻塞警告，未通过隐藏所有警告伪造无问题报告。

仍需真机验收：不同 Android 版本与厂商后台策略、蓝牙设备／编码、有线及 USB 输出、不同位深／采样率与超大曲库、持久授权撤销和大字体布局。没有进行物理耳机、蓝牙或 DAC 的实际音频测量。

本版暂不包括听力保护策略、用户歌单编辑、在线音乐、在线／音频内嵌歌词、无缝播放承诺、ReplayGain、USB 独占驱动及商店发布。离线分析不包含认证整曲动态或实时 FFT／DR；体感模式使用轻量实时 RMS 及运动数据驱动视觉。
