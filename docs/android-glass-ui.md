# 0.17.0 玻璃界面与播放恢复

开发者本轮明确采用最终明亮玻璃图标，并要求同步整体视觉、透明展开导航、圆形扩散、乐库底部模糊、文案精简、视觉对齐和播放恢复修复。设计采用现有原生 Compose，不引入网页或 GSAP 运行时。

## 材质与布局

`GlassEffects.kt` 统一透明亮面与定向细边，环境光由 `MoonlitBackdrop` 提供。内容保持锐利；整个页面背景延伸至透明导航下方，不为底栏另画底板或分隔线。当前项白色底 alpha 为 0.18，其余项只有图标；可访问名称、选中状态和 Tab 角色独立于可见文字保留。

主要内容水平边距统一为 24 dp；播放器顶部标题以完整视口为中心，而非左右按钮之间的剩余空间为中心。阅读正文限制行宽；列表、分析、知识及横屏控制可滚动。系统大字体不固定文字容器高度。

## 动画与模糊

展开标签与导航组尺寸采用阻尼 0.78、刚度 380 的弹簧。点击记录图标屏幕中心，再转换为页面局部坐标；420 ms 圆形裁剪从该点覆盖最远角。进入内容绘制在前，旧内容保留至扩散结束。重复点当前项不重复导航，Compose 动画遵循系统动画缩放。

乐库使用系统 `RenderEffect.createBlurEffect` 处理实际滚动内容，通过互补透明度遮罩将清晰层和高斯模糊层渐进混合；导航与迷你播放控件独立绘制并保持清楚。避免稀疏多点采样造成的文字多重轮廓。Android 12+ 提供此效果，Android 8–11 只做底部渐隐回退，尚未在旧版真机验证。

实现依据：[Android RenderEffect](https://developer.android.com/reference/android/graphics/RenderEffect)、[Compose 图形修饰符](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers)。

## 播放修复

此前乐库／队列再次选中当前暂停曲目会调用 `loadCurrent()`，停止播放器并重新打开文件。现在识别同一 URI 且未要求指定新起点的选择，直接恢复现有解码器；有错误、进程恢复后未加载解码器、明确从历史起点开始和换曲仍按需加载。

暂停时立即采样播放器时间。服务另保存最新播放意图，忽略快速恢复后才送达的旧 Paused 回调；迟到的 Playing 回调也不能覆盖新的暂停意图。只有真正加载新曲目才记录新播放访问，恢复不重复登记。前台服务已存在时不重复启动。

设备测试覆盖 MP3、WAV、FLAC、AAC、ALAC 的同曲恢复、位置和时间线保持，以及快速暂停／恢复。测试记录的约 117–126 ms 是从发命令到收到播放状态的模拟器耗时，包含轮询间隔，不是可听出声延迟或真机性能承诺。蓝牙、耳机输出、厂商系统和真实物理触感需真机验收。
